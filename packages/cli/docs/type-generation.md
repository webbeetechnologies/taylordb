# Type Generation

The CLI can introspect a live TaylorDB app and emit a TypeScript file you can import directly into your query-builder setup. The generated file is runtime-first: it exports a real `taylorSchema` object plus a `TaylorDatabase` type inferred from that object.

## Command

```bash
taylordb generate-schema <appUrl> <output>
```

| Argument | Required | Description |
|----------|----------|-------------|
| `appUrl` | yes | Either the full TaylorDB app URL (e.g. `https://app.taylordb.ai/123`) **or** a bare UUID that identifies the database directly |
| `output` | yes | Path to the `.ts` file that will be created/overwritten (e.g. `src/taylorclient.types.ts`) |

You must be authenticated before running this command. Use `taylordb login` or `taylordb set-token <token>` first.

## What it accepts

### `appUrl` — two formats

**Full URL**
The numeric ID is extracted from the last URL path segment and resolved to an internal database UUID via the TaylorDB API.

```
https://app.taylordb.ai/workspaces/my-workspace/databases/42
                                                            ^^
                                                            parsed as the app ID
```

**Bare UUID**
If the value already matches `/^[0-9a-fA-F]{8}-…/`, it is used as-is without an extra lookup.

```
taylordb generate-schema 7f3e1c2a-0001-0002-0003-000000000000 ./types.ts
```

## What you get

A single `.ts` file is written to `<output>`. It contains:

### `taylorSchema` runtime object

Every table in your app becomes a property on `taylorSchema`. Every field is emitted using a field helper from `@taylordb/query-builder`.

```ts
export const taylorSchema = defineTaylorSchema({
  users: {
    id: autoNumberField(),
    name: textField({ required: true }),
    role: selectField({
      required: false,
      mode: 'single',
      options: ['admin', 'editor', 'viewer'] as const,
    }),
  },
});
```

Applications can inspect this object at runtime for validation/UI:

```ts
taylorSchema.users.role.type; // 'select'
taylorSchema.users.role.required; // false
taylorSchema.users.role.options; // readonly ['admin', 'editor', 'viewer']
```

### `TaylorDatabase` type

The root type you pass as the generic to `createQueryBuilder`. It is inferred from `taylorSchema`, so the runtime metadata and query-builder types stay in sync.

```ts
export type TaylorDatabase = InferTaylorDatabase<typeof taylorSchema>;
```

### Field mapping

The mapping from TaylorDB field type to generated runtime helper is:

| TaylorDB field type | Generated runtime helper |
|---------------------|--------------------------|
| `singleLineText` | `singleLineTextField({ required })` |
| `text` | `textField({ required })` |
| `longText` | `longTextField({ required })` |
| `url` | `urlField({ required })` |
| `email` | `emailField({ required })` |
| `phoneNumber` | `phoneNumberField({ required })` |
| `json` | `jsonField({ required })` |
| `number` | `numberField({ required })` |
| `currency` | `currencyField({ required })` |
| `percent` | `percentField({ required })` |
| `duration` | `durationField({ required })` |
| `position` | `positionField({ required })` |
| `rating` | `ratingField({ required })` |
| `count` | `countField({ required })` |
| `serial`, `decimalSerial` | `numberField({ required })` |
| `autoNumber`, system `id` | `autoNumberField()` |
| `checkbox` | `checkboxField({ required })` |
| `date` | `dateField({ required })` |
| `createdAt` | `createdAtField()` |
| `updatedAt` | `updatedAtField()` |
| `modifiedAt` | `modifiedAtField()` |
| `select` (single) | `selectField({ required, mode: 'single', options })` |
| `select` (multi) | `selectField({ required, mode: 'multi', options })` |
| `link` | `linkField({ required, linkedTo })` |
| `collaborators` | `collaboratorsField({ required })` |
| `modifiedBy` | `modifiedByField({ required })` |
| `createdBy` | `createdByField({ required })` |
| `attachment` | `attachmentField({ required })` |
| `button` | `buttonField({ required })` |
| `formula` | `formulaField({ returnType })` |
| `lookup` | `lookupField({ returnType })` |
| `rollup` | `rollupField({ returnType })` |
| `search` | `searchField()` |

The `required` value reflects whether the field is marked **required** in your TaylorDB schema. `InferTaylorDatabase` maps these runtime helpers back to the query-builder column types such as `TextColumnType`, `SingleSelectColumnType`, `LinkColumnType`, and `AutoGeneratedDateColumnType`.

Computed fields (`formula`, `lookup`, `rollup`) use `returnType` to infer their read shape and are not insertable or updatable. Fields with an unrecognised type but a known `returnType` (`string`, `number`, `boolean`, `date`) fall back to the matching generic field helper.

### Select-field options

For every `select` field, the allowed option values are embedded directly in the runtime field descriptor.

```ts
role: selectField({
  required: false,
  mode: 'single',
  options: ['admin', 'editor', 'viewer'] as const,
});
```

Those literal options are available at runtime and are also used to infer the allowed TypeScript values.

### Plugin types (when plugins exist)

If the app has any plugins configured, additional types are generated:

- `PluginActionType<I, O>` — generic wrapper `{ input: I; result: O }`.
- Per-action input/output types compiled from the plugin's JSON Schema.
- A `_plugins` property on `TaylorDatabase` mapping each plugin and action to its `PluginActionType`.

### Default system fields

Every table automatically includes these system-level fields (merged before your custom fields):

| Field | Type |
|-------|------|
| `id` | `autoNumberField()` |
| `createdAt` | `autoDateField()` |
| `updatedAt` | `autoDateField()` |

## Output example

```ts
import {
  autoDateField,
  autoNumberField,
  defineTaylorSchema,
  linkField,
  numberField,
  selectField,
  textField,
} from '@taylordb/query-builder';
import type { InferTaylorDatabase } from '@taylordb/query-builder';

export const taylorSchema = defineTaylorSchema({
  users: {
    id: autoNumberField(),
    createdAt: autoDateField(),
    updatedAt: autoDateField(),
    name: textField({ required: true }),
    email: textField({ required: true }),
    age: numberField({ required: false }),
    posts: linkField({ required: false, linkedTo: 'posts' }),
  },
  posts: {
    id: autoNumberField(),
    createdAt: autoDateField(),
    updatedAt: autoDateField(),
    title: textField({ required: true }),
    status: selectField({
      required: false,
      mode: 'single',
      options: ['draft', 'published', 'archived'] as const,
    }),
    author: linkField({ required: false, linkedTo: 'users' }),
  },
});

export type TaylorDatabase = InferTaylorDatabase<typeof taylorSchema>;
```

## Formatting

The generated file is automatically formatted using the nearest **Prettier** or **ESLint** config found by walking up from the output path. If neither is found the raw output is written as-is.

## Other CLI commands

| Command | Description |
|---------|-------------|
| `taylordb login` | Interactive email/password login, stores the token locally |
| `taylordb logout` | Invalidates the current session and clears the stored token |
| `taylordb me` | Prints the name and email of the currently authenticated user |
| `taylordb set-token <token>` | Stores a token directly without going through the login flow |
